This is a deterministic evidence-comparison tool. It preserves source restrictions and distinguishes incomplete metadata from incompatible conditions. It does not predict bioactivity or rank drug candidates.

Try the complete workflow

  1. Open , choose Load synthetic example, then Run analysis.
  2. Inspect the identifier status and normalized value for each input row. For example, 200 nM becomes 0.2 uM while the < relation and SD remain attached.
  3. Inspect the reference comparisons. Missing sample or control metadata stays visible as an incomplete comparison; it is not assumed to match.
  4. Inspect within-upload pairs. A different exposure time prevents a condition match. Simulated samples remain user-reported identities.
  5. Download the JSON report, normalized rows and comparison CSV. Replace the sample with your own file using the same schema.

Input format

CSV uses comma-separated UTF-8 text with one header row. Quoted commas, quoted newlines and UTF-8 BOM are supported. JSON accepts an array of objects or {"rows":[...]}. Maximum input size is 5 MB and 1,000 rows. Provide at least one of file, cid, inchikey, smiles or name.

ColumnsMeaning
row_idUnique user row label. Assigned automatically if absent. Duplicate labels are rejected.
file, cid, inchikey, smiles, nameExact catalog record filename, PubChem CID, full InChIKey, literal stored SMILES or name. Names alone yield candidates. All supplied exact identifiers must resolve consistently. No salt stripping, tautomer merging, connectivity-only matching or inferred stereochemistry is performed.
system, endpoint, layerExact recorded system and endpoint labels. Case and whitespace are normalized; biological aliases are not inferred. Layer codes: cell_phenotype, enzyme_function, direct_binding, chemical_function, recorded_function. An explicitly labelled direct-binding record is distinct from a functional phenotype.
value, relation, unitFinite scalar and one of =, <, <=, >, >=, range. For ranges, omit value and supply value_min/value_max with relation=range. Values are not read from free-text prose.
error, error_typeOptional nonnegative reported uncertainty and its type, such as SD or SEM. A reported SD/SEM is not converted into a confidence interval.
method, exposure_hoursRecorded method and nonnegative numeric exposure duration in hours. Similar-looking method labels are not automatically equated.
dose_value, dose_unitFixed test concentration. Required for percentage comparisons. A test dose never becomes an IC50.
sample_form, control, paperExplicit material description, control description and source identifier (prefer DOI or PMID:12345678). Do not fill missing reference metadata by assumption.
quantitative_allowedOptional false restriction disables quantitative use while preserving the raw result. This user-provided field does not grant permission to override a source restriction.

Download blank header template. Unknown units remain unconverted. Invalid rows are retained in the validation report and cannot support a condition-match conclusion.

Processing method

  1. Resolve catalog identifiers. Intersect all supplied exact identifier matches. A unique record is a catalog match, not independent confirmation of the physical sample. Conflicting or ambiguous identifiers remain unresolved. Exact SMILES text matching is not chemical graph parsing.
  2. Preserve result semantics. Convert M/mM/uM/nM/pM to uM and supported mass concentrations to ug/mL. Percent values remain percent. Mass and molar families are never interconverted. Bounds, ranges and uncertainty scale with the same positive unit factor; no bound becomes a point estimate.
  3. Select reference candidates. Use the resolved catalog record and, when supplied, the same system and endpoint. IC50, EC50 and GI50 remain separate endpoints. A name-only candidate remains identity-limited.
  4. Compare recorded conditions. Check system, endpoint, evidence layer, method, exposure, sample form, control, unit family and, where applicable, fixed dose. An explicit mismatch takes priority over missing metadata.
  5. Return explanations and provenance. Each assessment lists mismatches, absent/restricted information and its reference field ID, original source and evidence locator. The report records software version and the reference snapshot hash.

Interpret the assessment

AssessmentInterpretation
Same-study candidateRecorded required conditions and source agree. Confirm material, assay design, controls and replicate structure in the original. This is not statistical equivalence.
Recorded conditions matchRequired recorded fields agree across studies. Unmeasured design differences and study effects remain. No pooled estimate or potency ranking is returned.
Insufficient metadataIdentity, valid result representation, quantitative permission or required conditions are missing. This is not an inactive or negative result.
Incompatible conditionsAt least one explicit condition differs. The report states which condition. It does not discard the original evidence.
User-reported conditions matchWithin-upload fields agree. User identities, source claims and measurements are not independently verified.

The reference matrix includes qualitative and restricted results. Row counts are not independent experiment counts. Missing structured metadata does not prove the original publication omitted it.

Validation and present limits

Engineering validation covers exact/ambiguous/conflicting identifiers, scalar and censored results, ranges, negative percentage values, invalid concentrations, missing conditions, incompatible endpoints, fixed doses, cross-study handling, CSV quoting and formula-injection-safe exports. External scientific validation is pending. These checks do not establish a novel method, independently validated experimental performance or superiority to another application. A publication study still needs independently adjudicated literature cases, documented comparator methods, user evaluation and real biological use cases.

Reference condition completeness varies. No new structure recognition, fuzzy biological matching, target prediction, statistical significance testing, meta-analysis or clinical recommendation is provided. Within-upload pair analysis is limited to 150 rows; all uploads still receive row validation and reference matching.

Privacy and operation

Input files and pasted text are processed in memory in your browser. This module makes no outbound request with input data, uses no tracking, and does not persist input in cookies or browser storage. Clear the session or close the tab to discard it. Downloads contain the input and analysis you choose to save. Publication links open external resources when followed. There are no accounts, required emails, asynchronous jobs or private result links.

The analytical module runs as static same-origin files. The public host should provide valid HTTPS on port 443. Maintenance ownership and a five-year hosting commitment must be established by the operator before a journal proposal. This local software release does not claim a public HTTPS deployment.

Corrections and reference updates

The reference matrix is a persisted, derived table in both the formal and working database layers. Every row points back to its source record and field. Original measurements, units and scientific verification states remain in the source stores.

After an approved data correction, the managed release workflow rebuilds both reference tables and the web snapshot together. Withdrawn or newly restricted results are reevaluated using the current evidence and publication policies. The release check rejects stale source fingerprints. A mismatched browser snapshot and release marker blocks analysis until a consistent version is loaded.

Reports retain the reference generation and source hashes. Previously downloaded reports remain dated snapshots; rerun them after reference updates. Missing experimental conditions remain missing. Explicit positive and vehicle controls retain their roles and any recorded result details.

Data provenance and licence

The new analytical code and original documentation are provided under the MIT licence, permitting free non-commercial and commercial use. The software licence does not relicense primary publications, third-party content or pre-existing database assets. Consult original-source terms for reuse.

The public reference projection follows the current database publication scope and evidence contract. Explicit mirrors are collapsed. Pending, withheld and inapplicable results are not promoted to admitted reference results. This software release does not change scientific records or their verification status.
